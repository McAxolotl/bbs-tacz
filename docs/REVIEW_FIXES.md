# 完整审查、复现与修复记录

审查日期：2026-11-09。修复分别提交，版本固定为 `v1.0.0`。

## 版本锁定

- 复现：原 `mod_version=1.1.0`，Gradle 还自动附加 Minecraft 后缀；`VersionLockTest` 在修改前失败。
- 原因：项目没有贯彻用户固定版本约束。
- 修复：配置、manifest 和 Gradle 产物统一为 `v1.0.0`；添加构建保护与版本回归测试，不改动运行时逻辑。
- 验证：`./gradlew build`；查看发布 JAR 的 `fabric.mod.json`，版本须为 `v1.0.0`。

## 验证原则

每个功能问题先使用原实现执行可重复的原生重现，再修改对应生产代码，最后运行同一重现与既有回归。测试只创建隔离开发世界与新测试影片，不覆盖用户存档/影片。完整 GUI、渲染、音频、导出和多人边界的验证范围以各节实际结果为准。

## 第三人称手臂动画

- 修复前复现：`./gradlew runClient -Preview=ThirdPersonArmsReview`，未 tick 的形态绘制右臂角为 `0.0`，原生持枪参考为约 `-1.575`，测试失败。
- 根因：身体绘制错误地开启了原生 first-person hand 上下文，TACZ 因此把手臂归零；最高优先级快照 PA 层也对身体 TRS 返回零。额外存在静态预览未 tick 和空身体快照停用原生动画的问题。
- 修复：实际绘制前准备/推进代理会话，保留每个游戏 tick 只更新一次的保护；只有非空身体快照才禁止原生补偿。去掉身体的 hand 上下文，快照 PA 层输出真实身体 TRS 并在采样时禁用自身。真实玩家仍采样其自身动画，矩阵查询不 tick。
- 回归：同一原生重现检查未 tick 预览与空姿态绑定；原有身体/腕部、装备与抛壳矩阵 smoke 检查继续执行。

## 第一人称手臂皮肤

- 修复前复现：`./gradlew runClient -Preview=FirstPersonSkinReview`，先放入待刷新的无关材质批次，左右手选中皮肤像素均为 `0`；无干扰批次的旧测试不足以复现用户问题。
- 根因：全局 vertex-format hook 只在第一个刷新层绑定选中皮肤；该层可能不是手臂，后续原生手臂/袖层还会重新绑定原玩家皮肤。
- 修复：将 BBS 纹理注册为原生纹理别名，由代理玩家返回它，原生手臂、袖层及身体渲染按材质身份绑定皮肤；不再依赖刷新顺序。别名每次绑定查询 BBS 当前纹理，支持重载/动画且不拥有底层 GL 资源。断开连接仅释放别名；取消选中皮肤回退到来源玩家皮肤。
- 验证：有/无待刷新的外部批次、左右手和袖层、相同 Link 复用、BBS 纹理重载、别名关闭/断线资源所有权、默认皮肤回退。原生重现报告 `PASS`，有干扰时左右手各 `14,406` 个选中皮肤像素。`./gradlew build` 通过。

## F6 第一人称回放与导出

- 修复前复现：原生 `F6ExportReview` 通过公开录制 API、编辑器 `applyRecordedKeyframes`、影片保存/读取与真实 F6 按键执行，姿态保存成功，但导出预热立即取消，无视频产生。
- 根因：编辑器冻结帧与服务端 `FILM_EDITOR` 预览共用影片 ID；F6 调用原生切换接口时把旧预览当成正在播放的影片并停止。清理预览后还存在服务端回复到达前就取消预热的异步竞态。此外第一人称目标曾由任意最新编辑器/冻结帧事件覆盖。
- 修复：仅为 TACZ 第一人称影片清理同 ID 的冻结/旧播放，使用有序原生 STOP→播放请求释放服务端编辑器预览；预热等待实际世界控制器（启动回复最多等待 30 秒，取消/退出清理等待状态）。世界播放优先于预览，冻结帧不劫持第一人称目标，预览引用使用弱引用注册表。
- 验证：同一 F6 链路使用提前准备好的原生枪械录制/保存；空手观众播放，预热暂停/恢复，注入更晚的预览事件验证所有权。报告 `PASS`；导出 64 帧 H.264 / 320×180 / 30 FPS，时长 2.133 秒，实际记录到第一人称绘制 166 次。`ffprobe` 解码信息通过，抽帧可见真实第一人称检视枪械。音轨另见后续音效验证。

## TACZ 回放音效

- 修复前复现：`PlaybackAudioReview` 使用真实、可解析的 AK47 换弹/射击声音与公开录制 API；声音实例存在，但影片保存/读取后音频片段为 `0`。
- 根因：旧代码只保存视觉快照与动画指令，不保存已解析的声音；快照回放不会运行原生声音监听器，无法凭视觉姿态重新得到随机音高和精确打断时刻。
- 修复：监听 TACZ 最终解析后的声音实例及原生停止调用，记录实际资源、音量、音高、开始与停止时间；停录时烘焙确定性的 PCM/WAV 并保存为普通 BBS 音频片段。亚 tick 起点用前置静音保留，停止/录制末尾裁切，不在录制时回播新片段。重录只替换本 replay 的区间，保留区间外与其他音轨，并禁止监听旧枪声轨道。已有录制音轨的播放仅抑制重复的原生声音，不抑制射击/弹丸通知。
- 暂停审查：原生 BBS 世界音频 context 的 `playing` 不随 controller 暂停；复现暂停后音源仍播放。为含本模组音轨的世界回放同步播放/暂停与零 partial 时间，保留 BBS 的 seek/resume/源释放机制。
- 验证：保存/读取 3 个声音片段；换弹原声 0.44 秒经原随机/指定音高与停止截断后约 0.31 秒；普通 BBS 离线混音为非零 PCM。通过原生世界渲染 context 与 OpenAL 验证 play/pause/seek/resume/outside/stop。`AudioRetakeReview` 修复前能听到旧轨道，修复后 `false`，头/尾及其他用户/演员音轨均保留。8 项 PCM 单测检查重采样、声道隔离、亚 tick、截断和无效/溢出输入。
- 集成验证：`F6AudioExportReview` 通过公开录制→编辑器应用→保存/读取→真实 F6→FFmpeg→BBS 原生音频后混音链路。H.264 视频中检测到所选皮肤 `3,202` 个特征像素；AAC 解码 `311,978` 个非零字节，第一人称实际绘制 163 次。
- 资源审查：实际固定依赖的 BBS 二进制已经按 `Sound.getPath()` 解析 `tacz_sounds`，并非资源路径错误；`NativeSoundExportReview` 的正确 48 kHz 对照混音通过，未修改该原生逻辑。
- 数据边界：音频文件遵循 BBS 外部资产约定，位于 `assets/audio/bbs_tacz/`，分享影片时需一同分享这些资产。旧影片若没有声音数据，无法精确恢复原音高/打断时刻，应重新录制该轨道；不伪造“已恢复”的音效。枪包/生成音频不打包进模组 JAR。

## F6 零延迟启动边界

- 复现：同一原生 F6 影片将视频延迟设为 `0`，导出直接进入 RECORDING，服务端回复尚未到达就结束；`F6NoDelayExportReview` 失败。
- 修复：仅对 TACZ 第一人称影片把传给内部 begin 的延迟保证为至少 1 ms，仍使用原生预热准备与暂停/恢复链路等待实际播放；不修改用户设置，不影响普通 F4 或其他影片。
- 验证：同一零延迟重现 `PASS`，真实视频生成且第一人称绘制 53 次；增加 ModifyArg 参数类型与实际调用点审计，构建通过。

## 多控制器与双端爬行状态

- 修复前复现：`CrawlOwnershipReview` 让 A 第一人称影片爬行，关闭无关 B 后，A 仍是当前目标但玩家高度由 `0.6` 变回 `1.8`，测试失败。
- 根因：任何 controller 的 SHUTDOWN 都会释放玩家全部爬行状态，演员/摄像机未分配独立所有者。补充双端测试还发现 Minecraft `Entity.equals` 按实体 ID 比较，内置服务端与客户端的同 ID 实体被普通 WeakHashMap 合并。
- 修复：爬行保存一个原始还原点，由演员绑定、服务端 ActionPlayer、第一人称摄像机分别拥有请求；最近的请求生效，释放一个请求不会释放其他请求。使用弱对象身份键隔离客户端、服务端和所有者；最后一个所有者释放后恢复原姿态/游泳/强制状态。绑定释放时保留仍有效的 leaning pitch。
- 验证：无关 B 关闭后高度仍为 `0.6`；临时 false 覆盖释放后回到 A 的 true；停止 A 无残留。内置服务端独立所有者及最终还原通过；3 项弱身份键单测防止相等 ID 合并。`CrawlOwnershipReview`、构建、Mixin 审计均 `PASS`。

## F6 取消与重试

- 复现：公开 F6 session.start 后同 tick cancel，20 tick 后服务端/客户端均仍在播放；晚到的 play 回复重新创建影片，`F6CancelReview` 失败。
- 修复：为原生有序回复分配每影片启动票据，只丢弃被取消的那次回复，不丢弃更新的重试；取消时停止已有客户端控制器，并发送幂等服务端 STOP，不用可能再次开播的 toggle。等待票据在退出/断线清理，并有过期上限。
- 验证：同 tick 取消后 `client=false / server=false`；取消后立即重试保留新的播放；已创建控制器的取消也不残留、不重启。原生 `F6CancelReview` 和 3 项票据单测 `PASS`，构建通过。
