## 修复前的原生复现

| 问题 | 原生观察 | 根因 |
| --- | --- | --- |
| 新 take 提取枪声 | Alt→Ctrl→F6 的影片出现 8 个音频剪辑 | 旧 `RecordedAudio` 在停录时烘焙 WAV 并追加 `AudioClip` |
| F6 不导出 | 编辑器 fp=true，服务端旧文件 fp=false；停在预热 | 启动只发影片 ID，没有同步当前编辑器影片 |
| F4 动画速度不一致 | 同一捕获区间世界 2.4 秒、枪械 18.878408942 秒 | 世界固定视频步长，SBM/TACZ 用真实纳秒，物理弹簧又在独立线程积分 |
| 连发节奏不一致 | 66ms 三连发的三个效果被压到同一视频时间 | 原生 `scheduleAtFixedRate` 的真实毫秒没有跟随视频时间 |
| 普通游玩调度回归风险 | 客户端 SUCCESS，但服务器 NETWORK_FAIL，alpha 约 1026ms | 将历史任务时钟用于普通游玩会违反 TACZ 时间戳窗口；现已限制为导出期间 |
| Ctrl 开始时方向/时间失配 | 首次客户端 tick=1，服务端已 tick=20 | 客户端影片/资源未加载完成，服务端已执行弹丸动作 |
| 回拨重复弹道 | 四颗弹丸回拨后变为八次出生 | `ActionPlayer.goTo` 倒序遍历时仍执行瞬时枪火/弹丸 |
| Ctrl 额外实时弹丸 | 回放中实时 shoot 返回 SUCCESS，服务器也 SUCCESS | 实时鼠标输入/晚到的预测与录制弹丸叠加 |
| 漏播末尾弹丸 | 姿态影片末尾 52，弹丸动作在 57 | 服务端动作录制 tick 与客户端姿态游标漂移；影片时长不包含动作末尾 |
| 同 tick 暂停丢失声音 | 暂停回放时原有 voice 消失；旧判定的负对照稳定失败 | 播放→暂停将渲染小数归零，被当作回拖而停止声音 |
| F6 结束/退出时动作列表崩溃 | MP4 已生成，但服务端在 `ActionManager.tick` 的 `ArrayList.removeIf` 抛出 CME | 原生 tick/停止/断线回调重入修改注册表；原生 `stopFor` 回调可确定性复现 |
| 无影片上下文的动作发射后异常 | 完整 smoke 在直接 `applyAction(..., null, ...)` 发射后 NPE | 影片所有权登记把空 Film 传给不接受空键的弱身份表 |
| 被打断的换弹声音仍在视频中 | stopFrame=-1，停止后仍有 30390 个非零 PCM 字节 | BBS 临时声音捕获只跟踪 loop 停止，one-shot 混音忽略停止帧 |

## 实现

1. `ExportTimebase` 对齐捕获帧的世界时间，导出开始/结束保持时钟连续；`ClockedSpring` 按同一时钟推进原有弹簧积分。连发任务只在固定时间导出期间改用时钟队列，保留原生取消/异常与普通游玩网络语义。
2. 新录制使用同步的 `bbs_tacz:sounds` 通道保存原生资源名、最终声源参数、起点与停止事件。播放仍调用 TACZ `SoundPlayManager`，实际实例是 `GunSoundInstance`。新 take **不创建音频剪辑、不生成枪声音频资产**。F4/F6 使用 BBS 原生 Minecraft 声音监听器进行视频后混音；临时混音 WAV 是封装中间文件，不是影片剪辑。
3. F6 和 Ctrl 启动同步当前影片，停止同 ID 的编辑器/冻结/旧播放，服务端原子创建并暂停 NORMAL 播放；对应客户端首帧就绪才恢复。Ctrl 普通播放跟随服务端动作时钟，避免慢帧累计漂移。
4. TACZ 弹丸/击发记录跟随客户端录制游标。旧的延后动作也纳入影片时长，不在姿态末尾被截掉。
5. seek 保留持久场景恢复动作，但不再倒序发射瞬时弹丸/枪火；只清理当前影片拥有的弹丸。回放拥有玩家时阻止实时开火与晚到预测，取消旧枪械任务。由旋转后真实速度推导朝向并初始化上一帧数据，原生碰撞、重力、伤害、穿透和爆炸逻辑保持 TACZ 实现。
6. 原生声音显式停止写入临时视频捕获行，one-shot 混音也遵循 `endFrame`。暂停、定位、恢复、控制器关闭和旧 take 隔离有原生 OpenAL 检查。同 tick 的播放→暂停只复位渲染小数，不销毁原声道。
7. 动作注册表使用带稳定身份条目的快照列表，支持原生 `Iterator.remove`，保留原生 tick/stop 和装备归还逻辑；清理回调修改列表不会导致 CME 或误删新播放。测试结果包含测试世界退出，Gradle 再检查本次新崩溃报告；意外断线/报告缺失/超时均失败。
8. 无影片上下文的直接弹丸动作继续使用原生物理，不绑定影片生命周期；空影片清理不操作实体。完整 smoke 另检查影片清理不会删除这种真实弹丸。

## 复测入口

完整串行入口：`scripts/verify-replays.sh`。每个场景单独运行：

```bash
./gradlew runClient -Preview=场景类名
```

报告缺失或不是 `PASS` 会使 Gradle 返回失败。所有场景只创建隔离的开发平坦世界，测试源码与探针不进入发布 JAR。

关键场景：

- `F4ClockReview`：真实 F4，含 held frames，比较捕获帧内世界/枪械时间。
- `F4BurstClockReview`：160ms 慢帧三连发、真实服务器射击、周期与视频导出。
- `HotkeyWorkflowReview`：默认右 Alt→右 Ctrl→F6，非测试专用停录/应用接口，不手动保存录制后的影片。
- `CtrlStartupReview`：客户端首帧与服务端动作开始的握手。
- `F6DraftExportReview`：刚改第一人称标志但未保存的影片。
- `ProjectileReplayReview`：多 yaw/pitch 真实击发、出生数量、速度/朝向、回拨、实时输入隔离及 F6 同帧渲染唯一性。
- `PlaybackAudioReview` / `NativeInterruptionExportReview` / `AudioRetakeReview`：原生声音 codec、OpenAL 生命周期、停止后 PCM 为零、旧格式轨道隔离。
- `MultiGunWorkflowReview` / `F4MultiGunExportReview`：AK47、M4A1、Glock 17、AA12、RPG7 的实际开火、ADS、行走、跑动、趴下，以及检视→改装→多配件视角→反复关开、换弹/近战/开火打断；分别验证 Alt/Ctrl/F6 与实时 F4。
- `F6AudioExportReview`：实际 H.264/AAC 解码和形态所选皮肤像素检查。
- `ActionTailDurationReview`：序列化与开关动作后的末尾时长。
- `ActionLifecycleReview`：原生停止/断线回调重入及借用装备归还；`ReviewHealthFailureReview` 为测试崩溃检测的故意失败负对照，不在正常通过列表中。

### 可复现的操作步骤

1. 使用本项目固定的前置版本和默认枪包；创建 BBS 影片，选择独立 TACZ 形态，启用 first-person replay，并选择形态皮肤；视频设置中启用“导出音频”。
2. 右 Alt 开始录制，依次对五枪执行持枪/ADS、走路射击、检视→改装→瞄具/枪口/握把/枪托切换、反复关闭/打开、换弹→近战打断、检视→改装、换弹→开火打断、走路/跑步/趴下；右 Alt 停止，不添加枪声音频剪辑。
3. 右 Ctrl 播放，检查声音、姿态与实际弹丸；暂停/恢复/回拖，检查 voice 与旧飞行实体；播放拥有玩家时尝试开火，确认不会增加第二批弹丸。
4. F6 导出，包括仅改编辑器 first-person 标志而未手动保存、延迟 0 和取消后重试；确认 tick 0 开始、完整片长及原生声音。
5. 实时 F4 执行同一五枪组合并导出。对比捕获帧内世界/GunTime 的增量，而非与导出所花的墙上时间比较。
6. 使用 `scripts/audit-replay-media.py` 完整解码实际 MP4，并抽帧对比；检查弹道实体出生数与每帧 ID 唯一性，不能把散弹的不同颗粒误认成重复渲染。

## 验证边界

- 自动验证使用固定的 BBS 2.7、TACZ Refabricated 1.0.0-forge1.2.0+mc1.20.1、PA 1.0.2-rc1+1.20 与原生单人集成服务器、无额外光影。独立多人服务器、额外枪包和光影组合仍需单独测试。
- 新影片保存的是原生资源命令，不复制枪包音频；回放机器需要安装对应枪包。旧版 WAV 音轨保留兼容性，但不能恢复当时未保存的原生随机参数/停止事件，建议重新录制旧 take。
- seek 不倒序创建瞬时弹丸，而不是重建任意历史时刻整个世界的物理状态。正常播放仍执行真实原生弹道。
- GPU/逻辑/媒体解码检查不等于全部第三方枪包在全部子帧逐像素相同。
