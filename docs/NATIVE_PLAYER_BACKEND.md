# 为什么独立 TACZ 形态是当前主路径

## 已采纳的范围决定

1. 用户最初要求 ModelForm 兼容。
2. 后续讨论原生 player 的 MobForm 能否更等价。
3. 最终决定：**新形态如果覆盖工作，就不需要 ModelForm 或 MobForm 路径**。

因此 v1.0.0 的实现是 `TaczForm extends Form`，只提供独立原生玩家形态；旧的双后端建议在这里被替代。没有偷偷继承 MobForm，也没有继续注册 ModelForm 的程序化 animator。

## 原生 player 身份不仅是一个模型名称

仅把生物 ID 写成 `minecraft:player` 不能得到完整 TACZ 兼容：原生 layer 要读九格热栏、选中槽、副手、姿态和原生 gun operator/PA 数据，还需要区分实际发射者与渲染代理。

新形态管理专用 `TaczVisualPlayer`：

- 完整装备和热栏；实际 Actor 无玩家背包时从 replay 读取。
- 宽/细手臂及皮肤纹理。
- 移动、头身相对角度、swim/lean/crawl/ADS 视觉状态。
- 实际演员与代理的 muzzle 身份转换；不会为了代理重广播 gameplay 事件。
- 回放使用保存的求值姿态；实时非玩家角色才运行代理原生动画会话。

代理从不加入世界、不承担射击或碰撞。真正的弹丸和爬行仍发生在服务器实际演员上。

## 如果是 BBS 作者来做：可推断的接口方向

这是根据 BBS 源码结构做出的设计推断，**不是声称作者本人作过承诺**。

合理的做法是使用公开 addon 注册事件、通用 Form/rig/pose/matrix 接口和原生 renderer；把 TACZ 的状态/时间/身份桥放在 provider 或附属模组内，不让 BBS 核心到处导入枪械类。

当前实现沿用这个边界。少量 Mixin 针对发布包中没有公共访问接口的原生接缝；不修改两个上游仓库，不打包它们的类。将来如果上游公开可恢复时钟、原生玩家 provider 或 emitter 快照 API，可以替换这些接缝，而不用更改影片的形态类型。

## 等价性来自整条变换链

- 原生 PlayerRenderer 的起身/爬行旋转和渲染偏移。
- PA 的整体 anchor、body bend、肢体 bend 与 item transform。
- 作者姿态在原生结果之后应用。
- 原生 TACZ 的手持、腰部和背部装备层。
- 历史发射时刻下的完整锚点/物品/shell 定位链。

只复制六个手臂/腿部角度仍会让枪械、附件和弹壳错位。只在当前手腕上补画历史弹壳也不能支持拖动、暂停或换枪。

## 独立形态不是“所有验收自动通过”

新形态去掉了未知自定义 rig 的转换问题，但仍必须验证录制协议、GUI 状态嵌套、动画打断、随机特效、帧率、共享模型恢复和服务端行为。自动化矩阵/绘制/弹道检查与所有枪包逐像素验收是不同层级。

自定义几何、其他形态、全部光影/加速渲染器的兼容不属于当前已经验证的原生玩家路径。需要这些能力时应明确增加独立 backend 和验收，不应再次以近似 ModelForm 姿态冒充等价。
